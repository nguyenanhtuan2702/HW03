# AI Critique - Task 1

The AI-generated checklist covered three Web Admin screens, but it initially blurred the distinction between documented requirements and usability heuristics. For example, it treated a loading indicator as if the assignment's IA-04 category required one. It also expected confirmation before deleting a category or coupon. Both checks are worth keeping because they can reveal usability problems, but the specifications for those features only require adding, viewing, and deleting. The AI inferred obligations from familiar interface patterns without tracing each expectation to the relevant requirement. Its automated checks also used evidence that was too narrow for the conclusions drawn. At 375 CSS pixels, the script marked a partly clipped category field as a failure. A follow-up browser run completed the create, view, and delete flows for both categories and coupons after scrolling. That supported a pass for task completion and left a separate finding about clipping. For the Delete buttons, the accessibility tree showed identical names. That observation alone could not establish whether a screen reader would announce the row context. My manual Windows Narrator check passed, so the final record identifies that result as a manual check and preserves what the automated inspection found. The principle I would carry into another assignment is to define what evidence would establish each result before asking AI to write or run a test. I would check every expectation against the specification, use actual browser interactions for usability claims, and record who performed each check so another reviewer can see what the evidence supports.
